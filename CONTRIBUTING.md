# Contributing

Thanks for helping. Please read the [Code of Conduct](CODE_OF_CONDUCT.md) first, and
report security issues privately as described in [SECURITY.md](SECURITY.md).

## Setup
Requires [uv](https://docs.astral.sh/uv/) (it installs the right Python for you) and a
container runtime such as Docker or OrbStack.

```sh
git clone https://github.com/jhanvi0905/immicite.git
cd immicite
uv sync                  # install dependencies into .venv
cp .env.example .env     # local config; never committed
docker compose up -d     # Postgres 17 + pgvector on localhost:5432
uv run alembic upgrade head
```

## Everyday commands
```sh
uv run pytest                        # tests (integration tests need the database)
uv run ruff check                    # lint
uv run ruff format                   # format
uv run lint-imports                  # layer boundaries
uv run immicite ingest --authority act   # pull sources; also --source SLUG, --dry-run
uv run immicite status               # what the corpus holds
uv run uvicorn app.main:app --reload # run the API on http://localhost:8000
```

To add a document to the corpus, add an entry to `sources.yaml` and run the ingest.
A page entry has no slug: it is derived from the page's address.

## Pull request workflow
1. For anything beyond a small fix, open an issue first so the approach can be agreed.
2. Branch from `main` and keep the change small and focused.
3. Read [docs/architecture.md](docs/architecture.md) and
   [docs/decisions/](docs/decisions/) before touching a layer boundary or an accepted
   decision. A change to one needs a new or updated ADR in the same pull request.
4. Add or update tests. Unit tests use fake providers and never touch the network.
5. Run the tests, lint and format commands above.
6. Open the pull request and complete the template, including eval numbers if scores
   changed. CI must pass before merge.

## Eval cases are human-written
Files in `evals/cases/` are written and edited by a human, never generated by a model or
coding agent. Each expected ref must be checked by a person against the official source.
A model-written eval set measures agreement with a model, not correctness, and it leaks
the system's own biases into its scores.

Feedback and citation reports are triaged by a human before any of them becomes a case.

## Never commit
- Secrets or `.env` files.
- Government page text. `data/` is gitignored, and CI fails if anything under it is tracked.
